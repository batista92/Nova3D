# Nova3D AI Gate

Status: Gate #5 approved on 2026-09-25.

The gate tests whether a new agent can deliver a small complete game from the
distributed Nova3D product, without the CityBuilder conversation history or
access to internal implementation as its starting context.

## Isolation

The evaluator receives only:

1. the user brief below;
2. a project generated by `dotnet new nova3d --physics --ui`;
3. the documentation and agent skill distributed in that project;
4. public/local Nova3D packages.

The evaluator must not read `Samples/`, CityBuilder scenes or this gate's
expected findings before its first working Release build. It may inspect public
package APIs and follow links shipped in the generated project.

Create Marble3D in a separate Git repository. Never add game code to Nova3D.
Suspected toolkit defects are recorded first; another pass owns toolkit fixes.

## User brief

Create `Marble3D`, a small 3D obstacle-course game in which the player rolls a
sphere to the finish. Deliver:

- main menu;
- one placeholder obstacle course;
- at least one checkpoint and respawn;
- visible run timer;
- music or sound effect using MonoGame audio;
- pause/settings flow with persisted settings;
- victory and defeat states;
- keyboard controls and usable Gum navigation;
- self-contained Windows x64 executable.

Use Nova3D public APIs. Keep rendering, physics and gameplay state separate.
Do not copy Nova3D source into the game. Placeholder art is acceptable; visual
polish is not the gate.

## Required evidence in the game repository

Create `Docs/AI_GATE_REPORT.md` containing:

```text
Environment
  Nova3D package versions/commit
  OS, backend and Release resolution

Context log
  document/recipe opened | reason | before/after first successful build

Interventions
  question or manual action | why the agent could not continue alone

Validation
  Release build command/result
  publish command/result
  executable launched outside repository: yes/no
  menu/input/audio/victory/defeat visually tested: yes/no per item

Autonomy
  files read before first build
  manual interventions count
  copied internal Nova3D code: must be no
```

Copy `Docs/NOVA3D_EVALUATION_TEMPLATE.md` to
`Docs/NOVA3D_EVALUATION.md`. Record every real problem, including documentation
gaps and game-owned mistakes. Do not invent entries to improve coverage.

## Gate result

Approve only when all are true:

- Release build and self-contained publish succeed;
- published executable starts without the repository as working directory;
- menu, playable course, checkpoint, timer, audio, settings, victory and defeat
  are observed working;
- physics and UI remain optional Nova3D packages;
- ownership/lifecycle rules are preserved;
- no Nova3D implementation source is copied;
- every toolkit problem has reproduction, evidence and owner;
- required context and manual interventions are reported honestly.

Build success alone cannot approve visual, input, audio or platform behavior.

## `arcade3d` preset decision

Decision for v0.1: **do not create the preset yet**.

Evidence:

- `PhysicsPlayground` and `RollingBall` repeat physics-world setup;
- `GumMenus` and `RollingBall` repeat Gum host/screen-stack setup;
- those repeated module choices are already composed by `--physics --ui`;
- only `RollingBall` currently demonstrates the complete arcade game flow.

A preset would currently encode one game's structure rather than proven
game-neutral repetition. Re-evaluate after Marble3D and one additional external
game. Extract only boilerplate repeated by both; do not turn checkpoint, timer,
camera or game-state policy into Nova3D engine APIs.

## 2026-09-25 result

An independent agent created the external `Marble3D` repository using only the
generated project, distributed documentation, skill and public/local packages.

Automated result:

- baseline and completed Release builds: pass, zero warnings/errors;
- self-contained `win-x64` publish: pass;
- published executable startup smoke (five seconds): pass;
- manual intervention during initial implementation: none;
- post-delivery audit interventions: one;
- copied Nova3D implementation source: none;
- real product problems found: one.

`N3D-001`: the generated template omitted `.gitignore`, exposing `bin/` and
`obj/` as untracked files. The audit also showed that the owner taxonomy lacked
`Nova3D.Templates`. Both are corrected in the toolkit and guarded by template
smoke validation.

Manual acceptance result:

- human visual rendering: pass;
- menu, audio and rolling-ball physics: pass;
- checkpoint activation and victory condition: pass;
- Gate #5 accepted by the product owner.

The complete clean-machine matrix and individual gamepad, resize, settings
persistence and defeat-path checks remain useful release checks, but they do not
block this gate after product acceptance.

Known non-blocking observation: while the sphere occupies the checkpoint, green
checkpoint geometry is visible across its lower portion. Ownership remains
`Unknown` until a minimal reproduction distinguishes game/course geometry
intersection from a rendering defect. Do not tune Nova3D rendering to hide it
without that diagnosis.
